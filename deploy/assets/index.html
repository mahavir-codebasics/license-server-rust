Quick start

Bootstrap an account, issue a signed license, validate it — three calls. The first POST /v1/accounts returns your admin token.

# 1 — bootstrap your organization (returns the first admin token)
curl -s -X POST https://license.itih.in/v1/accounts \
  -H 'content-type: application/json' \
  -d '{"slug":"acme","name":"Acme Inc"}'

# 2 — create a product + policy, then issue a signed license key
curl -s -X POST https://license.itih.in/v1/accounts/$ACCOUNT_ID/licenses \
  -H "authorization: Bearer $ADMIN_TOKEN" -H 'content-type: application/json' \
  -d '{"product_id":"…","policy_id":"…"}'

# 3 — validate it from your app (also available over gRPC :9090)
curl -s -X POST https://license.itih.in/v1/accounts/$ACCOUNT_ID/licenses/$LICENSE_ID/actions/validate \
  -H "authorization: Bearer $ADMIN_TOKEN"

Everything a licensing backend needs

Phases 0–8 of the v1 roadmap are complete — 127 tests, live multi-DB isolation suites, and a wrk-measured hot path.

🔑

Cryptographic license keys

Ed25519, ECDSA-P256, RSA-2048 and JWT signing schemes, plus AES-256-GCM encrypt-then-sign license files (PEM certificates).

🏢

Multi-tenant by design

Every resource is org-scoped, enforced at the repository layer and — on Postgres — by Row-Level Security. Cross-tenant access is tested against all three databases.

⚡

gRPC hot path

Validate / activate / check-in / check-out over tonic on :9090 for sub-millisecond machine-to-server traffic; REST for everything else.

⏱️

Background jobs

Cron sweeps for expiry, culling and retirement, HMAC-signed webhooks with retries, and a full audit event log.

🪪

OIDC SSO + tokens

Just-in-time provisioning from your identity provider, bearer-token API auth, Redis token-bucket rate limiting and Idempotency-Key support.

🗄️

Three databases

PostgreSQL (UUIDv7 + JSONB + RLS), MySQL, and SQLite backends behind one Repository trait. Time-ordered IDs keep inserts append-mostly.
